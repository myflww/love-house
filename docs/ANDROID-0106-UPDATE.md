这次更新包含手机内运行的共享引擎，不是只把旧 APK 的版本号改成桌面版本。下述能力已接入，实际验收及兼容范围见本文后半部分。开发用 unsigned APK 与测试 APK 不用于日常安装。

## 本轮接入的能力

新版通过 Chaquopy 内置 Python 3.12，在应用私有目录运行与桌面相同版本的 `MemoryHost`。完整界面复用桌面页面并适配手机布局；外层继续保留旧版离线记忆入口。

| 能力 | 新版的实现方式 |
|---|---|
| 保存、查找与召回 | 使用共享记忆核心，保留原文、时间和来源；不依靠旧移动版的标签星图代替记忆引擎 |
| 记忆整理 | 在目标记忆库中配置模型 API，再按设置整理；调用由用户所选服务按实际用量计费 |
| 人格 | 与共享核心一样，允许从有来源的记忆中逐渐形成，保留用户手动关闭的选择 |
| 更正与历史 | 保留原话及后续变化，区分当前材料、历史和用户明确停用或忘记的内容 |
| 多记忆库 | 各库独立；Agent 使用为其创建的连接和授权范围，不因同一手机存在多个库就能读取全部存档 |
| 星云与界面 | 使用现有神经星图与完整管理界面；手机适配不代表所有尺寸与设备性能已验收 |
| 备份与迁移 | 保留单库分享 JSON、阅读导出与明确的旧库迁移流程；导入不会执行文件中的连接或模型配置 |

原文保存、已有记忆检索与本地管理不需要整理模型 Key。模型整理和人格提炼等需要模型参与的步骤，必须先在目标库配置相应服务；只启动软件不会替用户自动填写或购买 API。

## 安装与升级条件

- 目标系统为 Android 8.0+，目标架构为 `arm64-v8a` 和 `x86_64`。32 位 Android 设备不在新版内置 Python 的发行范围内。
- 包名保持 `io.github.myflww.lovehouse.preview`，新版 `versionCode` 为 `4`，版本名为 `0.10.6rc1`。
- 覆盖升级必须继续使用原持久发行私钥。另生成一个签名，即使包名相同，也不能覆盖旧版并保留其应用数据。
- 本页下载指向已验收的原签名主程序。主包、冻结 QA 和额外验收探针均核对原证书；QA-only、unsigned、私钥和口令不进入发行下载。原始输入与流程保留在[签名交接书](ANDROID-0106-SIGNING-HANDOFF.md)。
- 升级前先从旧版导出每个库的 JSON。不要先卸载旧版，也不要清除应用数据。

## 旧库如何进入完整记忆

旧版离线库继续保留原来的 WebView 来源与 IndexedDB，不会因为加入新引擎就被当作空库覆盖。旧库和完整引擎是两个独立的数据区域：

1. 在旧版离线入口选择要迁移的那个库，先导出一份 JSON 备份。
2. 点击“迁移当前旧库”，阅读确认内容后才将该库通过脱敏分享格式导入完整引擎。
3. 打开“完整记忆”，核对新库名称、原文、回复和记录数量。
4. 原来的离线库仍保留。迁移后继续在旧库编辑的内容不会自动同步到新库，两个入口也不会自动双向合并。

“打开完整记忆”用于进入新引擎，不等于授权批量上传或自动迁移全部旧库。迁移只处理选中的库，不带入模型密钥或启用导入文件内的连接。相同内容的重复迁移会核对已有回执，避免因误点反复创建同一份库；修改过的旧库仍应在迁移前确认导入目标与备份。

新版桌面或完整引擎导出的 JSON，请在“完整记忆”的分享/导入页面读取。旧离线入口仅保留旧格式能力，不支持所有新配置，例如时间保留模式的 `max_nodes:null`。“迁移当前旧库”受原离线导出单包 32 MiB 限制；超过限制会保留原库并报告错误，不会为了满足单包上限删除较早记录。

## 连接配置应该交给谁

配置必须交给**实际运行这条 Agent 的宿主**，例如相应电脑或服务器上的 Harness、AstrBot 或其他具备工具配置能力的程序。普通聊天网页仅能显示文字时，不能靠粘贴配置获得自动采集能力。

| Agent 实际运行的位置 | 应当怎样连接 |
|---|---|
| 这台 Android 手机上的可配置宿主 | 连接手机本机爱之屋的地址与凭据；先测试工具读写，再核对宿主是否持续上报真实轮次 |
| Windows 或 Mac | 在那台电脑持续运行爱之屋，将该电脑生成的配置交给同机 Agent；手机可通过已配置的个人 HTTPS 服务管理同一份远端库 |
| 阿里云等服务器上的 AstrBot / 其他宿主 | 在服务器运行爱之屋服务，绑定那条鱼的稳定身份和已授权活动来源；向服务器宿主安装其配置，再用手机打开该服务的 HTTPS 管理入口 |

手机完整引擎仅监听 `http://127.0.0.1:8768`。`127.0.0.1` 永远代表运行客户端的那台设备：把手机的这个地址复制到云服务器，只会让云服务器寻找它自己，不会连上手机。新版不会默认向局域网或公网暴露手机管理服务。

手机打开远端 HTTPS 服务管理的是**远端保存的库**。手机本机完整引擎、旧版离线库和远端服务是三种不同的数据位置，打开远端页面不会自动上传本机记忆，也不会把它们合并。

## 自动记录与后台运行的边界

爱之屋接收宿主明确上报的真实对话与事件，再整理为可追溯的经历。它不读取 QQ、浏览器或其他 App 的私有聊天，也不因为安装网络权限就知道那条鱼在其他平台做了什么。

同一条鱼在多个软件中的经历，可以由同一宿主统一上报，或为同一个 Agent 身份登记多个已授权活动来源。每个来源仍须真实接入；仅复制 MCP 配置、工具在线或收到一次手工事件，不代表所有软件的活动都会持续记录。

**手机不是全天在线的服务器。** 关闭完整记忆界面、系统省电或结束应用进程可能停止本机接收；本轮不承诺在这些情况下保持后台采集。再次打开会恢复已经落盘的记忆，同一存档的有效连接配置可以继续使用，但离线期间宿主未投递的内容是否补送取决于该宿主的持久队列，不能宣称必然自动补齐。需要全天候记录时，应让电脑或服务器上的爱之屋与宿主持久在线。

## 网络、凭据与本机数据

新版增加 `INTERNET` 权限，用于本机 HTTP 引擎、用户配置的模型 API 和更新检查。原生网络策略只允许 `127.0.0.1` 使用 HTTP；远端服务和模型接口应使用 HTTPS。网络权限不是其他 App 的聊天、文件或操作权限。

模型凭据通过 Android Keystore 管理的密钥加密，密文保存在应用私有区域；Keystore 适配失败时应明确报告，不把它当作已经安全保存。此说明不承诺所有设备都提供硬件级安全元件。记忆正文仍保存在应用私有文件中，不等于全部记忆数据库已经额外端到端加密。

系统文件选择器只在用户主动导入、导出时打开。不需要相机、录音、无障碍或广泛存储权限。卸载应用或清除应用数据会删除本机记忆和凭据；迁移、清理手机或更换设备前请导出备份。设备之间没有自动云同步。
