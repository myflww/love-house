# Agent 身份与经历记忆（0.8.0）

爱之屋围绕同一条鱼真实经历过的事情保存记忆：**什么时候、经历什么、原话明确表达的原因、实际得到的结果。** QQ 会话、网页和工具是经历的来源，不是每换一个软件就新建一条鱼；工具名称、参数和调用堆栈也不应成为主要的生活记忆。

本文依据 0.8.0 当前代码说明已实现能力与限制。来源登记、SDK、经历整理和 AstrBot 实验适配已经加入；这不代表已经观察到所有软件中的全部活动。

## 主页面留下什么

“她的经历”按时间展示经过、已表达的原因和结果，保留各句话的说话者与依据。程序没有获得原因或结果时明确保持未知，不为了完整故事猜出“她为什么这样想”或“最后一定成功了”。

| 内容 | 0.8.0 的处理 |
|---|---|
| 发生时间 | 采用来源中的实际发生时间；未知则标记未知。存入时间另列，不冒充过去发生的时间 |
| 经历什么 | 引用已核对的原文或实际观察，区分观察到的事情、听到的话、助手自述与当时意图 |
| 为什么 | 只保留来源明确说出的缘由，标记用户原话、对方原话或助手自述；引用存在不等于心理动机已证实 |
| 结果 | 工具依据的状态只能称来源报告；用户／助手说完成了仍是被归属的陈述，不等于外部目标已独立验证 |
| 涉及的人、地点和平台 | 从已有原文或来源资料提取，不依据昵称猜身份，不补造没出现过的人物 |

原始资料继续保留作核对依据。原始工具观察默认从实际记忆库的主要图谱显示中隐藏；用户选择、召回、聚焦或打开“显示原始工具依据”时仍可查看，不会因此删掉原文。已有原始对话和旧版记忆也保留，不能说升级已经把所有旧资料自动写成了新经历。

工具结果可以支持一件真实发生的事，但不需要把“调用了哪一个函数、传了哪些内部参数”逐条写成日记。技术细节适合留在来源或诊断层；工具观察尚未整理时，界面应说明原始资料已保存、经历尚待整理。

## 整理模型与程序各自负责什么

配置并启用的整理模型可以从本批资料提出经历、事实、偏好、约定和关联。每批自动带上版本化整理准则，不需要用户反复粘贴。模型不能修改库归属、容量、淡化规则、使用次数、删除权限或原始对话。

新增的 episode 是受约束的经历结构。what 必需，reason 和 outcome 可以为空；有内容时只能提供本操作已经引用的 {id, role, quote}，参与者和地点同样使用引用。发生时间、来源角色、结果状态和来源版本由程序补齐。模型不能提交自由编造的经历正文来替换这些依据。

project_experience() 在展示和可回忆 JSON 中重新检查：

- 经历及引用都属于当前存档，来源仍存在且没有停用、忘记或更正失效。
- 引用仍逐字对应原来的角色和来源上下文，来源版本没有被改成另一段话。
- 来源只有截断摘录时，须取得本库完整档案才能核对超出摘录的引用；不能验证则保守不展示。
- 外部导入的同名 metadata 不能单凭形状就变成已经确认的真实经历。

安全投影通过后，经历可随 love-house-memory-context/v1 JSON 提供给 Agent，仍是带证据和归属的历史材料，不是系统指令或模型权重。图谱和人类页面使用可读文字，机器结构保留原文、角色、时间与来源。

同样的措辞在不同时间发生，不能仅因 key 或 atom 相同就合并成一次经历。只有同一 what 的已验证发生来源一致、原因和结果不冲突时，才能补充合并；相反结果、冲突来源与受保护旧设定进入审阅。跨软件的一项连续任务可以关联各阶段，但不能没有关联依据就拼成一段故事。

## 自主生活不必每次由主人确认

0.8.0 已有严格的自主观察分支：经历的主要事件必须有实际工具观察，结果也须来自工具观察或保持未知；原因可以保留助手明确自述，但 reason_verified 始终为假。通过来源、角色、版本、现实域、确定性和冲突检查后，这类自主经历可以自动入库，不必每件事都等待主人发言。

纯助手自述、准备做某事、非观察主事件、未知现实域、角色扮演或不确定内容不会因这个分支自动确认。普通事实、偏好、约定和人格也不能借“经历”分支绕过原有审阅。失败或中断本身可以是真实经历，不能被模型改写成成功。

## 一份持久身份，多个活动来源

当前以固定 library_id / agent_id 表示这条鱼的持久存档，新增来源登记表把每个宿主连接固定到该身份。来源有独立凭证、适配器类型、管理员登记的 runtime_agent_id 与允许平台范围；每个事件和上下文请求都须与登记值相符。

这是**登记过的适配器声明和凭证校验**，不是读取模型昵称后自动认出“同一个意识”，也不是对宿主执行器的远程身份证明。一个机器人账号可能承载多条鱼，一条鱼也可能在多个账号或软件中活动，不能只按 QQ 号、窗口标题或模型厂商 Key 合并身份。

实际配置应先选择这条鱼的已有存档，再登记驱动它的宿主。能够确认归属的同一宿主，其已接入的平台活动可自动汇入原库；另一个独立执行器需要为同一条鱼增加来源。不会要求每开一段 QQ 对话就复制一份新库，也不会把用户本人或别的 Agent 的无关活动混进来。

旧单窗口连接继续保留原授权，不会被升级静默扩大。它适用于还没有稳定宿主身份适配的客户端。“整连接”只是范围设置，单独打开这个开关不等于已经完成 Agent 全活动验证。

## 养鱼的实际接入路线

| 路线 | 当前能力和边界 |
|---|---|
| DeepSeek Harness | 保留已有窗口插件及真实宿主回调；窗口范围不自动扩大，不宣称因此已验证宿主外全部活动 |
| 登记来源 SDK | SourceClient 支持真实对话和实际观察的上报、固定身份上下文查询、幂等、私有待交队列和重连；接入执行器需要实际调用这些接口 |
| AstrBot + SnowLuma + QQ | 已提供可打包的 AstrBot 实验插件，多个明确登记的消息来源可归入同一鱼；尚未完成真实 AstrBot / SnowLuma / QQ 账号环境验收 |
| 独立浏览器、其他软件、主动任务 | 已登记且实际接入 SDK 或宿主钩子的观察才能进入；未接入执行器不会自动被监控 |

来源私有配置不是模型厂商 API Key。聊天模型沿用宿主自身配置；爱之屋整理模型是另一个可选配置。配置文件须由来源宿主所在机器加载，不能直接把 Mac 的本机路径搬到云服务器。

当前来源 SDK 标准化完整对话与实际观察，不接受任意新活动类型便宣称可回忆。受支持的登记来源会在接收前拒绝归属不符、未允许的平台或未知规范化类型，避免将错误数据反复入图。未适配的事件覆盖应明确标注，不能以“连接就绪”代替“真实经历已经落盘”。

### AstrBot 中的人物与状态

UMO 是消息来源和情节分区，不直接等于长期记忆身份。实验插件由管理员把多个属于同一 Agent 的 UMO 放入同一绑定；一个 UMO 重复路由到两条鱼时拒绝归属不清的配置。

平台 user 发言可能来自第三方，不能当成主人的原话。服务端保留外部参与者标记与发送者标识，经历显示“对方原话”；这类来源的偏好、事实、约定和人格变化先审阅，不自动归到主人。

实验插件只在最终生成结果时配对完整对话；生成、宿主发送阶段、平台接受、收件人送达和已读是不同状态。没有送达或阅读凭据时不能声称对方已看到。实际工具返回的文字可成为观察，不保存工具参数、工具名或私有推理来冒充生活经历。

详细安装、缺口与合成验收步骤见 [AstrBot 实验插件说明](../extensions/astrbot-love-house/README.md)。运行服务、云端凭据、常驻进程与远程管理仍需对应部署支持；当前桌面版没有自动跨设备同步或通用远程库选择器。

## 迁移、回忆与已知限制

分享或备份导入为新身份时，可信导入器在来源编号和回执映射完成后调用 rebind_experiences_after_import()，重设本地身份与来源版本，再复核角色和逐字依据。不能验证的经历保守暂不展示，原文保留。日常读取不会自动重新签名，避免把后来编辑过的来源重新包装成旧经历。

0.7.0 的连续淡化与原文保留规则继续适用，不按固定条数或统一天数挤掉经历。模型整理按已启用配置、批次和预算逐步运行；保存了一万份原始资料不等于已经整理成一万件生活事件。旧已完成任务不因升级自动重写全部历史。

当前“她的经历”页面一次可增至 100 条，其余仍在存档，可到节点列表继续搜索；这只是显示预算。未通过安全投影的条目会统计为依据暂不可用，不把缺失说成没有记忆。来源页面显示最近接收、暂停、断开和队列相关状态，但 full_activity_coverage_verified 仍为假。

## 验收应围绕生活经历

应在临时鱼与合成资料上验证：同一鱼在两个已登记来源交流、观察和完成一项事情，按同一身份回忆；未登记来源和另一条鱼不进入；时间未知不冒充今天；原因保留自述而不补造；失败不变成功；断线后补交且不重复；原文修改或明确忘记后旧经历不复活。

还需要在真实宿主版本、账号、平台、独立执行器和云端运行环境逐项验收。源码和本地契约测试通过，不能据此宣称已经覆盖一条鱼在所有软件里的全部经历。
