# 架构

## 一句话

一张加权图，三个操作：**扩散**（读）、**强化**（学）、**衰减**（忘）。

```
         ┌────────────── Brain ──────────────┐
写入 ──▶ │ nodes{}  edges{}  half_life{}     │ ──▶ recall()  ──▶ 带路径的命中
         │   ↑         ↑                     │
         │ add/link   reinforce（赫布）        │
         │            forget（半衰期）         │
         └───────────────────────────────────┘
```

整个库只有一个类，两个字典。没有缓存层，没有索引，没有后台线程。
这是刻意的：**可解释的前提是每一步你都能读代码读出来。**

---

## 数据模型

`brain.json`：

```json
{
  "version": 1,
  "name": "brain",
  "half_life": { "concept": null, "fact": 365, "episode": 60, "doc": 240 },
  "meta": { "created": 1761900000, "updated": 1761903600 },
  "nodes": {
    "n_ab12": {
      "id": "n_ab12",
      "kind": "concept",
      "label": "激活扩散",
      "text": "从查询点燃若干节点……",
      "tags": ["检索", "算法"],
      "salience": 0.9,
      "created": 1761900000,
      "reinforced": 1761903600,
      "recalls": 4,
      "meta": { "source": "docs/架构.md#激活扩散" }
    }
  },
  "edges": {
    "n_ab12|n_cd34": { "w": 0.62, "n": 3, "last": 1761903600 }
  }
}
```

- **边的键是 `小id|大id`**，所以是无向边；权重对称。
- 没有存向量。字面重合度是**检索时现算**的（节点数百个时开销可忽略）。
- `meta` 是一个自由字典，`ingest` 用它记录来源，你也可以塞任何东西。

## 四个公式

### 1. 点火（查询 → 种子分）

对每个节点算一个 0 上不封顶的分：

```
inter = |Q ∩ V|                                   Q=查询的二元组集合, V=节点的
base  = max( dice(Q,V), 0.7 × inter / |Q| )       ← 两种口径取大
tag   = 命中的标签数（标签是人工语义钩子，权重给满）
score = (base^1.2 + 0.5·min(1,tag)) × (0.55 + 0.45·salience)
```

**为什么两种口径取大**：`dice` 会被长文档稀释（分母大），`containment` 只看
查询被覆盖了多少。短问句用后者才召得回来，长文档用前者才排得准。

**为什么乘显著性**：同样命中，重要的那条应该先被点燃。这也是"遗忘"能起作用的前提 ——
衰减后的节点在点火阶段就已经不占优势了。

`base < 0.06` 且没有标签命中 → 直接丢弃。宁可没有种子。

### 2. 扩散（1 → 多跳）

```
act = seeds / max(seeds)
重复 steps 次：
    add[b] = max over a 的 ( act[a] × w(a,b) × damping )
    next   = add ∪ { a : max(act[a] × 0.86, add[a]) }      ← 保留系数，防止原点被冲掉
    act    = next / max(next)
```

三个细节：

- **用 `max` 而不是 `sum`**：多条路到达同一节点时取最强的那条，避免"连接多的节点"
  因为被反复加总而爆炸。这是 PageRank 和加权投票的区别。
- **每步重新归一化**：让每跳的量级可比，分数才不是"跳数越多越大"。
- **保留系数 0.86**：不加这个，走两跳之后种子节点自己就消失了，
  可解释性会丢掉"从哪来"。

`damping` 控制衰减，默认 0.6。它决定了"三跳之外还值不值得看"。

### 3. 强化（赫布）

```
一次召回里同时出现的节点，两两之间：
    w ← w + lr × (1 - w)        lr = 0.14
节点：
    salience ← salience × 0.66 + 0.34
    recalls  += 1
```

`(1-w)` 是饱和项：越接近 1 加得越少，永远到不了 1。
这避免了"用一百次就变成绝对真理"，也让强连接之间还能保持区分度。

**为什么是两两**：3 个节点一起出现 → 3 条边。这是组合数增长，
所以 `reinforce` 默认只取前 4 条命中，再多就是噪音且开销陡增。

### 4. 衰减（遗忘）

```
节点：salience ← salience × 0.5^(天数 / half_life)
      跌破 0.05 → 连同所有边一起删除
边：  w ← w × 0.5^(天数 / 90)
      跌破 0.02 → 删除
```

半衰期按类型配置。这是刻意的**分级遗忘**：

| 类型 | 半衰期 | 理由 |
|---|---|---|
| `concept` / `source` | 永不 | 定义和出处不会过期 |
| `fact` / `preference` | 365 天 | 一年后该重新确认 |
| `doc` | 240 天 | 文档会过时 |
| `episode` | 60 天 | 具体发生过的事，两个月忘一半才像人 |

**衰减只在调用 `forget()` 时发生**，没有后台定时器。这是为了可预测性：
你不会在某个查询里突然发现节点没了。挂 cron 就能自动化。

## 复杂度

| 操作 | 复杂度 | 备注 |
|---|---|---|
| `add` | O(1) | 二元组现算 |
| `link` | O(1) | |
| `recall` | O(N·L + E·steps) | N=节点数，L=平均二元组数 |
| `reinforce` | O(k²) | k=传入节点数 |
| `forget` | O(N + E) | |
| `auto_link` | O(N·L) | 每次 add 都会做，N 大时是瓶颈 |

实测：1000 节点 / 3000 边，`recall` 约 8ms（M 系列 Mac，纯 Python）。
几千节点以内完全够用。十万级要换存储。

## 三个取舍

### 为什么不用向量库

向量库回答"哪段文字最像"，不回答"这条知识和那条知识怎么互相唤起"。
第二个问题才是"想起"的本质：你听到"赫布学习"，会想到"遗忘曲线"，
不是因为它俩字面相似，而是因为**它们在你的图里是连着的**。

而且向量库不可解释。用户问"为什么召回了这条"，你只能给一个 0.83。
这里你能给整条路径。

真要语义检索，`encode` 换成 embedding 就行，图结构不动。

### 为什么不做 LLM 抽取

很多记忆项目用 LLM 把对话抽成三元组。听起来很美，代价是：
你不知道某条知识为什么在库里，也没法修 —— 抽取是黑箱。

这里只做两种切分：**按 Markdown 标题切**、**人工 `add`**。
标题就是人写下的结构，用它比猜准。

### 为什么是单个 JSON 文件

因为要能 `git diff`。知识库应该和代码一样进版本控制：
你能看到"上周我加了什么，删了什么，哪条边变粗了"。

## 扩展点

| 想改什么 | 动哪里 |
|---|---|
| 换语义检索 | `Brain(encode=你的函数)`，返回 `set`；或自定义 `SeedScorer` |
| 换存储 | 实现 `StorageBackend`（`load` / `save`），传给 `Brain(storage=...)` |
| 加类型 | `nkb/config.py` 的 `DEFAULT_HALF_LIFE` 加一项 |
| 改渲染格式 | `nkb/render/` 加一个函数 + `register_renderer` |
| 加工具 | `nkb/adapters/mcp.py` 的 `TOOLS` + `call_tool` 加分支 |
| 调默认参数 | `nkb.toml` 或环境变量，不要改代码 |
| 改前端 | `nkb/viz/web/index.html`，单文件，改完刷新即生效 |

## 模块边界

```
core/brain.py  ──依赖──▶ storage.base / retrieval.* / config / errors / utils
retrieval/*    ──依赖──▶ errors（不碰 core，可以单独 import 使用）
adapters/*     ──依赖──▶ core / render / viz
viz/builder    ──依赖──▶ 无（只读 brain.export() 的字典）
```

**`retrieval` 不依赖 `core`。** 这条约束是刻意的：
扩散算法应该能被单独拿去用、单独被测。改算法时不需要构造一个 `Brain`。
