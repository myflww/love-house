# WorkBuddy 连接与排查

适用于爱之屋 0.8.0rc2。WorkBuddy 桌面端的 MCP 配置加载与用户 Hook 支持会随版本变化；以下步骤不会把工具连通当成自动存档已启用。

1. 打开爱之屋，选择目标记忆库，为当前聊天窗口创建独立连接。选择 WorkBuddy，复制向导生成的配置；使用页面显示的真实配置路径，不要从程序安装目录推测数据目录。
2. 将 MCP 配置交给有本机配置能力的 Agent 安装，或合并进 WorkBuddy 的 MCP 配置。保留原有连接器，勿用整文件替换。安装后回读核对命令、参数与配置文件存在性。
3. 在 WorkBuddy「连接器 → 自定义连接器」核对并信任爱之屋。若当前窗口没有出现记忆工具，重载连接器或重启 WorkBuddy，再打开目标窗口。用户在 WorkBuddy 5.9.3 的反馈中需要信任和重启；这不是所有版本必需的固定步骤。
4. 调用 `memory_status`、`memory_bootstrap` 检查是否加载、绑定了哪个窗口以及记忆读取结果。空库读取完成不代表出错；`all_memory_loaded: true` 和 `total_memories: 0` 表示确实没有记忆。
5. MCP 只是读写记忆的工具通道。要自动保存每轮内容，宿主必须真实调用来源适配器并上报完整轮次。手工运行一次 Hook 只能证明这次事件被接收，不能证明后续每轮都能自动记录。请用真实对话验证，并对照最近接收时间、事件数与实际记忆。

## 各状态的含义

| 状态 | 下一步 |
| --- | --- |
| 配置已生成，工具未加载 | 核对完整路径、信任连接器；必要时重启宿主 |
| 工具已连接，等待窗口绑定 | 由目标窗口的来源适配器上报来源身份；MCP 手动补录不会抢占窗口 |
| 已收到来源事件 | 检查事件与记忆是否对应；仅在宿主继续上报时才会继续保存 |
| 换了聊天窗口 | 使用重新绑定流程，确认后重新加载新配置；历史记忆保留，旧凭据作废 |

## WorkBuddy 自动 Hook 的边界

用户在 WorkBuddy 5.9.3 的复盘中，向 `~/.workbuddy/settings.json` 和 `~/.codebuddy/settings.json` 写入 Hook 探针后未观察到回调。引擎存在内部 Hook 运行时，并不能证明桌面端会加载这些用户设置。本版不会把这两处设置作为已验证的自动安装路径。

爱之屋生成的正则匹配模式使用 `.*`。不同宿主对 `*` 的解释可能不同：不要将某一宿主的通配符语法直接复制给正则引擎。安装前需要校验具体宿主的配置格式。

手机本机离线记忆与连接到个人 HTTPS 服务是两种使用方式。手机可以管理服务中的连接；WorkBuddy 的宿主配置仍需在运行 WorkBuddy 的电脑上完成。iPhone 主屏幕网页和 Android APK 不会在手机后台读取电脑窗口。

## 配置及隐私

Windows 默认将用户数据置于 `%LOCALAPPDATA%\LoveHouse`，与 `%LOCALAPPDATA%\Programs\LoveHouse` 程序目录分开；自定义数据目录、便携模式和其他系统应始终以连接向导显示的实际路径为准。MCP 配置和 Hook 配置可能包含连接凭据，只交给自己信任的宿主，不要上传到公开 Issue。

本次公开测试只使用虚构窗口标识和虚构对话。复盘中的真实连接、记忆库和会话标识不作为产品示例发布。
