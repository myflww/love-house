# 自适应记忆与 AI 整理规则（0.7.0）

爱之屋的个人记忆库不再用固定节点数量挤掉旧记录，也没有统一保存期限。原文保留，随时间与有效使用变化的是可提取性、显示强度与关联权重。淡化、休眠、事实失效和用户明确删除是不同状态。

## 研究依据与采用边界

- Anderson 与 Schooler（1991）研究了记忆可用性与频率、最近性及先前接触模式的关系。这里借鉴这些维度建立可解释的连续模型，不把人脑视作固定条数缓存。[原论文](https://journals.sagepub.com/doi/abs/10.1111/j.1467-9280.1991.tb00174.x)
- Roediger 与 Karpicke（2006）的实验发现，提取练习可以改善延迟后的保持。软件据此区分实际向 Agent 提供记忆与后台浏览，不把打开列表、预览、导出当作练习。[原论文摘要](https://pubmed.ncbi.nlm.nih.gov/16507066/)
- Cepeda 等（2008）表明，学习间隔和最终保持间隔存在交互，不能把某个固定天数当作普适规律。软件只借鉴分散使用值得单独考虑；当前饱和间隔加权并未精确复现论文的最优间隔曲面。[原论文](https://doi.org/10.1111/j.1467-9280.2008.02209.x)
- Murre 与 Dros（2015）的复现以单个受试者学习无意义音节为材料。它支持研究遗忘曲线的价值，不能据此给所有个人经历指定统一有效期。[原论文](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0120644)

以下公式与参数是工程近似，没有用用户的人类记忆数据标定。它计算软件中的可提取性指标，不是人脑成功回忆概率，也不改变陈述真伪、确认状态或人格权限。

## 连续淡化模型

```text
A(t) = Σ weight_j × (1 + elapsed_j / scale)^(-d)
strength(t) = 1 - (1 - base_salience)^A(t)
```

创建记录提供权重 1；有效取回或明确重提增加练习轨迹。间隔采用有界权重：`0.75 + min(1.25, log1p(spacing_days)/2)`。同一时间短促重复不会无限累加。

平缓、均衡、较快对应 `d=0.35 / 0.5 / 0.7`；`scale=7×86400` 秒是数值计算尺度。**第七天没有任何保护结束、删除或有效性改变；第 30 天、第 200 天同样没有期限断崖。** 三档仅调整曲线倾向。

每节点保存最近 16 条有效轨迹；更早轨迹压缩为总权重和加权时间，避免元信息随对话次数无限膨胀。历史预览不使用未来练习的质量。用户确认的重要性、已有情绪锚点和未完承诺沿用保护规则；整理模型不能擅自制造这些确认。

## 程序必须保证的底层规则

1. 新旧个人库自动启用自适应策略，节点数量上限为 `None`。旧环境变量不能让数量驱逐重新生效。旧 CLI 实验库未开启此策略时，仍可保留其显式有限配置。
2. 自动淡化不物理删除原文节点或弱边。另有新信息到来，不会仅因数量使同一天或任何其他日期的记录消失。
3. 低强度记录仍保留，可通过明确线索、目录和原文读取寻找。停用、未来事实、已更正事实与用户明确忘记的内容，不能被使用强化复活。
4. 上下文取回只记录固定库内的节点 ID、类型和时间；不把查询正文写进使用日志。使用效果与下次对话入库或本库维护保存一同提交，失败保留待办。
5. 同节点、同类型的有效使用按 UTC 日期与滚动 24 小时去重。这是防刷和重试规则，不是记忆期限或人类认知结论。用户可关闭有效使用巩固。
6. 多个库完全独立；页面切库不会改变连接归属。导出、预览、查看规则不算有效使用。
7. 用户明确“忘记”继续清理原文及其派生资料与使用元信息。淡化不代替用户的删除权限。

## 整理大模型怎样参与

用户启用并配置整理模型后，程序自动给每一批请求附带版本化系统引导，以及本库存档的运行策略。无需用户重复粘贴规则。“整理准则”按钮可以查看实际使用的引导，不调用模型。

模型负责提炼事实、偏好、经历和约定，比较同义内容，提出关联、更正与待审阅候选。程序只接受既有白名单操作与输出结构，逐字核对证据、角色、原文边界、目标节点和固定库身份。

- 不因寒暄、重复、时间久或记录多而删原文。
- 不把同一轮的多个采集副本当作多份独立证据。
- 不把助手自述、小说、假设或角色扮演当成用户确认的现实。
- 否定、时间变化和冲突必须保留。语义归并不覆盖来源；改变同一属性时须明确标出更正目标。
- 人格和关系阶段等敏感推断供用户审阅，不由模型直接认定。
- 模型不能修改容量、淡化参数、使用次数、库归属或删除权限；输出代码、删除动作或额外权限字段会被拒绝。
- 没有可靠可提炼内容时可返回空操作，原始对话照样保存。

程序仍按用户启用状态、批次、材料字符预算和每日调用预算整理；排队不丢弃原文。材料字符计数包含运行策略，但不包含固定系统引导与模型输出，不能当作厂商精确 token 或费用上限。一天输入一万轮并不意味着必须同一天完成一万轮模型调用，也不会因此提高用户预算。

## 实际限制与兼容

取消逻辑数量驱逐不意味着物理磁盘、内存或运行时间无限。图谱仍用 JSON 保存，本轮没有偷偷迁移为 SQLite 图谱；使用元信息单独使用 SQLite。显示层已有粒子降档和列表分页，不能用显示预算删除存档。后续增量存储与大图分页需要独立迁移验收。

聊天单批输入、模型上下文、分享文件和备份恢复仍有各自操作预算；超出应明确提示、分批或保留队列，不以此删旧记录。历史聊天、笔记和手动内容目前随图谱完整保留；未宣称已经建立所有来源的独立原文冷档。

0.7.0 的个人库配置使用 `max_nodes:null`。回退到不理解该配置的旧程序时，需同时恢复升级前的数据副本；不要拿旧程序直接打开新版正在使用的数据。Windows/移动版同步共享代码并完成各自验证后再读取新版存档。

本机升级前的数据备份使用各库既有受管备份，不另存绕过遗忘清理的原文 ZIP；用户明确忘记时，该库旧备份仍会按既有规则清理。回退前先确认配套备份仍在，并另行处理升级后新增的资料。
