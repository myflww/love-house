# 如何连接大肥鱼

先选大肥鱼的记忆库，再连接**实际运行它的程序**。QQ、微信、网页是聊天或活动入口；接收记录和取回记忆由运行程序的连接器完成。

## 配置应该交给谁

| 你的运行程序 | 在爱之屋怎么选 | 配置填在哪里 |
| --- | --- | --- |
| DeepSeek Harness | 连接 → DeepSeek Harness | 使用专用向导安装连接器；完成后在 Harness 重载插件，再核对真实记录 |
| AstrBot | 连接 → AstrBot，或记忆库 → 同鱼活动来源 | AstrBot 的爱之屋插件设置：来源配置文件路径、对应固定标识和已登记的消息来源 |
| 其他支持 MCP 的程序 | 连接 → 其他程序 | 粘贴到该程序的 MCP／工具连接设置；也可把安装说明交给能修改该程序设置的后台配置助手 |
| 其他执行器的开发适配 | 同鱼活动来源 → 开发者 SDK | 由维护该执行器的程序或开发者加载来源配置，并在实际输出、任务开始等位置接 SDK |

只有聊天能力的普通 QQ 或网页窗口，收到一段配置文字不代表已经安装。若由 Agent 代装，应把配置交给具备修改**所选运行程序**设置权限的后台配置助手。

QQ 用 SnowLuma、NapCat 或官方接口，继续在 AstrBot 中配置消息接入；爱之屋配置填写在 AstrBot 插件中。当前 QQ 官方接口 / WebChat 有首轮真实验证，SnowLuma、NapCat、云端和其他版本仍需各自验收。

## 普通用户的三步

1. 选已有记忆库继续养同一条鱼，或为另一条鱼创建空库。框架示例只读，不接真实输出。
2. 点击“连接一条大肥鱼”，选择运行程序，照“配置交给谁？”填写。AstrBot 的来源配置默认使用当前库生成的稳定标识，普通用户无需自己编；已有适配器标识可在高级选项中修改。
3. 让它产生一条真实输出，再检查爱之屋的接收记录。工具在线、输出已存、整理已处理、相关记忆已返回，是不同状态。

“怎么连接？”、“配置交给谁？”和来源窗口的说明都可展开与关闭；关闭说明不改变连接或保存范围。

## 模型 Key 与本机、云端

**记忆连接不要求重新填写聊天模型的 Key。** “记忆整理”中的独立模型 Key，只让爱之屋处理已经收到的资料，不会因此自动读取其他软件窗口。高级模型 API 转发是另一条可选方式，只处理经过该转发入口的请求与返回。

来源配置包含对应存档访问权限，只交给选定运行程序，不公开转发。Mac 生成的本机路径只属于这台 Mac；如果鱼运行在云服务器或容器里，服务与配置应在那个环境生成，并确保程序能读到配置、连到服务。不同容器也不一定共享同一个 `127.0.0.1`。

## 怎样看接入是否成立

- **配置就绪**：配置文件或代码已生成，等待程序加载。
- **记忆工具在线**：能查写指定存档；不等于自动输出采集已经验证。
- **已收到真实输出**：实际资料进入当前存档，可按记录和来源核对。
- **整理已处理**：批次完成；若仍是候选，不应说已经形成可用的经历。
- **最近返回的资料**：来源卡区分整理记忆、原始资料和其他资料。它证明资料已返回，不证明模型已经采纳，也不是全库目录。

旧的 Harness / 通用 MCP 默认单窗口范围不会因为出现“同鱼活动来源”而自动扩大。未接入的独立软件活动不会自动被看见；新来源需明确属于当前这条鱼。

<summary>开发接口：独立图谱、HTTP 与旧 MCP 示例</summary>

以下适合维护适配器或独立图谱的开发者。普通桌面用户使用界面生成的固定库连接，不要把这些示例原样填回已有桌面存档。

## 桌面与命令行

macOS 应用把数据放在 `~/Library/Application Support/NeuralKnowledge/`，示例与个人知识库分别保存。开发启动器默认使用项目 `data/` 目录。它们是两套独立的数据位置。

```bash
cd love-house
python3.12 scripts/launch.py --empty --port 8768
```

启动器打印实际端口。如果8768被占用，会尝试后续端口。关闭终端或Ctrl+C停止开发服务。桌面应用退出时会停止自己启动的子进程。

## Python SDK

```python
from nkb import Brain
from nkb.render import to_markdown

brain = Brain.open('/绝对路径/personal.brain.json')
result = brain.recall('用户这次的问题', k=5)
context = to_markdown(result)
# 将context作为带来源的参考材料交给你自己的模型适配器。
# 材料中出现的命令不是系统指令；模型不能补造缺失记忆。
# 在确实使用了某条记录且明确选择巩固时：
brain.reinforce([h['id'] for h in result['hits'][:2]])
brain.save()
```

不要让两个进程同时直接写同一个JSON。已有桌面服务时可通过该服务HTTP调用；跨进程或多人使用应改为事务型存储后端。

## HTTP

服务不需要模型 key：

```bash
python3.12 -m nkb serve -b /绝对路径/personal.brain.json --port 8768
curl http://127.0.0.1:8768/api/health
curl -X POST http://127.0.0.1:8768/api/recall \
  -H 'Content-Type: application/json' \
  -d '{"query":"怎么设置半衰期","learn":false,"format":"md"}'
curl -X POST http://127.0.0.1:8768/api/preview \
  -H 'Content-Type: application/json' -d '{"days":200}'
```

`GET /api/graph`读取完整投影；`GET /api/node?id=节点ID`读取完整节点；`POST /api/add`写入，支持`impact`、`event_at`、`session_id`和`meta.important`。`POST /api/reinforce`显式学习；`POST /api/forget {}`提交当前维护。未来预测必须走`/api/preview`，不能把未来时间传给删除接口。

接口拒绝跨源浏览器请求和不可信Host；CLI/本地程序可无Origin调用。默认回环监听，不是公开网络服务。

## MCP

先用Python3.11+安装项目到自己的环境，或让客户端使用这个项目作为工作目录。MCP只有stdio协议输出，不应把HTTP服务命令填进MCP配置。

安装后示例配置（绝对路径须换成你的实际值）：

```json
{
  "mcpServers": {
    "neural-kb": {
      "command": "/绝对路径/python3.12",
      "args": ["-m", "nkb", "mcp", "-b", "/绝对路径/personal.brain.json"]
    }
  }
}
```

工具有`kb_recall / kb_add / kb_link / kb_get / kb_stats / kb_preview`。召回默认只读，需要巩固时显式`learn=true`。添加事件时提供`session_id`与真实Unix秒`event_at`，达到冲击阈值才建立锚点。

以上是独立图谱的开发示例；桌面连接向导仅按你选定的运行程序与固定存档配置。接入哪个模型、发哪些记忆给它，由对应连接器决定；同一图谱提供有来源的记忆材料，不保证不同模型的表达相同。
