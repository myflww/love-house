# 爱之屋 0.8.0 · 首轮真实养鱼验收

2026-10-30，在独立 macOS 实验目录运行官方 AstrBot 4.29.3，使用用户在本机填写的 DeepSeek 测试模型与 QQ 官方机器人。原有个人 Agent 存档不参与本次测试。私人身份、凭据、完整聊天和截图不随源码发布。

## 已实际验证

| 场景 | 实际观察 |
| --- | --- |
| 自动保存 | 实际 QQ 与 WebChat 最终轮次进入固定测试库，带真实来源与事件编号 |
| 清空上下文 | AstrBot 执行 /reset 后，仍可从该鱼存档取回原约定 |
| 同鱼跨平台 | 用户只在 QQ 修改随机口令，网页窗口不提供答案提问，返回正确的新口令和被替换旧值 |
| 另一鱼隔离 | 独立对照存档未取得 QQ 口令资料；模型也没有用它自己的其他约定冒充 |
| 未登记窗口 | 新 WebChat 窗口能正常聊天，但检测文字未进入两个测试库原始档案 |
| 离线补交 | 关闭爱之屋，AstrBot 继续完成真实对话；SDK 待交数量增加。重开原数据后队列归零，完整轮次恰好一份 |
| 凭据与身份恢复 | 爱之屋重启后仍用原控制器端口、固定存档及已保存整理凭据，无需重新输入 |
| 真实操作观察 | 实验专用零参数工具实际读取固定公开示例网页，返回 HTTP 200、实际标题与读取时间，原始观察已存档 |
| 模型整理 | 真正调用用户配置的模型，已完成一批6份资料；不合法可选机器字段退回逐字原文候选，不写成已确认事实 |

最后一项网页观察的完整经历整理单独核验，不以“原文已保存”冒充“经历已形成”。首次测试预算达到后停止新增调用，追加调用需用户确认。

## 实测暴露并修复

- DeepSeek 官方适配在默认推理模式下可耗尽有界 JSON 输出预算。对明确支持的官方端点与模型关闭该整理请求的推理模式；其他兼容厂商不强加字段，截断仍拒绝。
- 旧的长回复和更晚的网页复述可能挤掉 QQ 最新的短更新。明确询问某平台刚才/当前/最后的记录时，补回该平台最近两轮有效原话，并先为它们分配结构化预算。
- 可选 atom 字段不合规曾导致整批重复调用。现保留严格原子校验，只将该条的已校验原文降为待审候选，清除非法机器字段、模型摘要、目标更新与关联动作；其他证据或权限错误仍拒绝。
- 本次检索为空不代表整个存档为空；存档人格未设置也不改变宿主已配置人格，适配资料对此作了明确说明。

## 验收边界

这是特定版本和账号的首轮实机验证，不是长期稳定性认证。没有在 SnowLuma、OneBot、微信、阿里云、多主机或全部 AstrBot 版本中验证，也没有验证任意浏览器 GUI 操作。本次网页工具只有固定公开 URL，不能据此声称可以观察所有软件活动。

云端无界面服务、来源 SDK 和跨来源经历规则另有临时进程、假模型及合成资料测试；这些不能算真实云部署。Windows 和移动端需在各自环境同步并验收后发布。

原始记录和来源证明继续保留；模型声称“记得/不记得”不是唯一证据。判断应同时检查实际回执、固定库、检索材料、输出内容和队列状态。
