# 爱之屋：模型与 Harness 接入

本次 0.4 的主要入口是桌面设置中的“接入与记忆”，可自动生成当前用户的地址与配置。请优先参阅 [快速使用](../README.md) 和 [服务接口](API.md)。

- 模型 API：填写实际支持 Chat Completions 的厂商地址、模型和密钥，再把生成的本地地址与连接凭证填入你的聊天客户端。用户可以单独配置一个整理模型。
- Harness：向导先检测版本并预览计划，再应用自己的自动存档插件。精确验证版本 0.2.1-rc.3；宿主契约与实现见 [适配器](../extensions/deepseek-harness/README.md)。
- 原有 MCP 桥仍可用于兼容工具调用，但它自己无法监听“每轮结束”，不应当作自动捕获已经完成的证据。
- 心跳仅表示插件在线；第一条真实完整事件落盘后，才报告自动存档成功。
- 每个连接固定一个记忆库。切换星图不改绑。初始空库不需要添加教学内容或默认人格。

下面是旧版 0.3 接入记录，保留用于排查旧配置。它不是 0.4 新用户的操作步骤。

# 让 DeepSeek 接上长期记忆

知识星图负责本地记忆。DeepSeek或Harness先从这里读取相关记录，回答或完成任务后再写入有来源的新经历。模型接口本身不会替应用保存全部上下文，因此每次请求都由本地服务重新准备所需的记忆和有限历史。

官方依据：[DeepSeek多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat/)、[Harness MCP client](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md)。

## 界面的三个操作

1. **API聊天**：设置API Key和模型，每轮发送相关记忆/长期偏好/最近六轮，再保存这一轮的两方原文。
2. **记住这条**：把你明确指定的偏好、事实或重要经历保存下来。普通聊天不是全部永久保存。
3. **Harness接入**：复制Overlay，把记忆工具接到已有Harness；记忆服务不需要拿到Harness里的模型密钥。

名字、称呼、人设由你填写，保存后重启仍然存在。它们作为用户设定的风格材料，不把外部网页或过去助手的话提升为系统指令。

## 接入 Harness

打开桌面应用，进入“AI陪伴 → Harness接入”，复制配置，保存为`neural-memory.cordis.yml`。其中使用打包内Python和MCP桥，不直接打开共享JSON，因此桌面和Harness不会互相覆盖。

先保证你已有Harness中的官方`@deepseek-ai/dsh-mcp-client`与宿主版本相容，再按你当前Harness的方式加载该Overlay。例如官方的worked example使用：

```bash
dsh web --patch /绝对路径/neural-memory.cordis.yml
```

本项目不会自动改写你的全局Harness设置。应用内的“记忆自检”不调用模型，可先确认能读到个人库。即使界面正在显示框架示例，桥也只使用个人库。

可用工具包括读取记忆包、记录明确记忆、保存一轮对话、记录网页/工具事件和查看服务状态。网页操作仍由Harness已有的浏览器工具执行；知识星图只记录结果与来源，不替代Harness的权限判断，也不自行扫描网页或电脑。

验证方法：让Harness保存一个明确标为测试的偏好或事件，另开新会话，再用记忆工具查询。查看星图中的来源、会话和原文是否一致，而不只相信模型说“记住了”。

## 记忆如何保存

- 普通对话存成经历，正文是用户原话；助手回复另有角色标记，不自动变成用户事实。
- 默认200天窗口适用于普通经历；明确重要的偏好、事实和锚点按保护规则保留。
- 工具观察与Harness记录标明来源和确认状态。失败的网页操作也只能记录为失败，不能变成成功经历。
- 来源事件有请求编号，重试不会重复堆积同一轮记录。已按生命周期遗忘并删除的事件不另建无限账本。
- 所有实际放入发送材料包的节点都有ID；可在画布查看“这次带了哪些记忆”。

未填写Key时不会伪造AI回复。本次开发验收只使用离线的模拟传输检查流程，没有调用用户的真实DeepSeek账户。实际连接结果会在应用中如实显示。
