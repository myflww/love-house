# 爱之屋 macOS 0.9.1：WorkBuddy 连接修复

本轮承接另一台电脑的 [WorkBuddy 交接书](https://github.com/myflww/love-house/blob/07a67dc51bdaccc71957e6ea414cac976f841b0d/docs/MACOS-080RC2-WORKBUDDY-HANDOFF.md)，参考PR #9的固定提交`ab373b9f6d5b1763b14eb5903a66fb20775eda73`，逐项合并到Mac 0.9基础，保留独立助手输出、整理记忆检索、来源计数与原有库身份。没有用Windows工程覆盖Mac项目。

## 连接和配置

- 向导增加WorkBuddy入口。界面复制服务实际生成的私有配置文件路径，不从安装目录或MCP参数推算路径；文件缺失时给出本机正确目录及修复动作。
- 先预览，再由用户点击“备份并合并”，保留无关MCP配置，备份原字节并回读。完成后仍需在WorkBuddy中信任并加载工具。被动状态刷新不读取WorkBuddy配置文件。
- WorkBuddy全局配置中出现另一份爱之屋记忆连接器时，拒绝自动合并，提示使用独立环境或复用原连接；不自动删除其他条目，也不读取其他连接器的私有文件。此保护避免一段Agent上下文同时接触多个存档，不能代替宿主自身的工具隔离。
- 可读、可写、窗口绑定和宿主实际接收分别显示。普通MCP工具可用，不等于已经安装对话结束钩子；一次手工Hook只证明该次收到，不承诺未来自动采集。
- WorkBuddy桌面用户Hook支持仍未确认。当前Mac检测到已安装5.9.2，仅为版本观察；没有将Windows 5.9.3的实测结论写成Mac通过，没有修改用户的实际WorkBuddy设置。

## 固定窗口与管理权限

窗口策略使用`any / fixed / next_session`，实际来源单独保存在`bound_session_id`。旧的整连接或具体窗口格式按有效范围迁移，迁移不是扩大记录范围。

重新绑定需要本机界面明确确认。历史记忆保留，绑定代次递增、凭据换发；旧配置失效，新窗口必须由真实来源回调认领。MCP手动补录不能抢占一个尚未绑定的窗口。已有旧MCP进程可能需要重载，界面提供信任／重启提示。

管理接口要求本地UI的会话身份，匿名请求不能枚举和管理连接。Cookie为HttpOnly、SameSite=Strict，普通连接Bearer仍限制在自己的库和允许接口，不能借此取得管理权限。旧Harness工具只核对固定库身份与统计，不读取管理状态或枚举其他连接。无界面来源配置CLI先核验本机实例，再获取仅在内存中的普通UI会话。

这个措施不承诺抵御能够以同一系统用户运行、并主动打开本地管理界面的恶意进程。当前Mac分支没有远程网关和手机管理服务，本轮没有新增或宣称验证这些入口；交接书关于远程登录／CSRF和iPhone真机的项目仍由对应远程工程负责。

## 验证记录

所有自动检查使用临时库、虚构记录及假凭据；未新增真实模型调用。配置合并在隔离主目录验证，不操作真实WorkBuddy配置。

重点回归包括：实际路径、无关MCP保留、其他记忆连接阻止合并、未绑定手动写入拒绝、枚举策略迁移、旧凭据失效、跨库／跨窗口负面检查、一次Hook不等于全自动、匿名管理拒绝、异源拒绝、来源Bearer越权拒绝及0.9输出／快速回忆保留。

原生自检使用临时UI会话Cookie；先检查匿名管理401，再由根页面建立会话，不通过关闭鉴权来运行。包内自检核对`host_reported`及独立绑定字段，原生WKWebView还需实际打开WorkBuddy帮助、读取真实生成的私有文件路径并检查重启。

最终结果：835项后端回归完成，普通环境跳过2项后以指定AstrBot环境37项检查补验；19项桌面检查、23项Harness检查及26项新增／既有连接界面行为检查通过。完整包内检查与WKWebView原生首启、退出重开、配置路径及WorkBuddy帮助检查通过。

macOS构建号13已安装到原应用位置。升级后5个记忆库及节点数、回收站5个存档、10个连接的有效窗口范围、当前选库、整理设置和密钥元数据均保持。管理接口匿名请求返回401，普通UI会话可正常操作。原应用和停止写入时的完整数据目录已留作本机回滚副本。

上述结果不等于真实WorkBuddy自动存档或远程手机验收已通过；本轮没有修改用户的实际WorkBuddy配置。
