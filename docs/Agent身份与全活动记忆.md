# Agent 身份与全活动记忆

这是用户在 0.7.0 交付期间明确的产品定位，也是后续平台适配的统一准则。**爱之屋的归属中心是 Agent，聊天窗口和软件平台只是活动来源。** 本文是接入架构与验收目标，不表示目前已经发布所有平台的自动采集器。

## 一份身份，多种活动来源

一个稳定 Agent 身份对应一份独立存档。QQ、网页浏览、文件操作、外部工具、游戏和定时任务可以由不同来源连接汇入同一身份，不按每个 QQ 私聊机械拆成不同 Agent。更换窗口、模型或平台，不应自动更换记忆。

登记一个能够确认 Agent 身份的宿主后，该宿主驱动的多个软件活动应自动归属，不要求用户每换平台或每开会话重复绑定。只有活动由另一个独立执行器产生时，才需要增加来源。Agent 与不同人交流仍属于它的经历，但必须保留参与者区别，不能把第三方偏好写成主人的偏好。

既有底层已经使用固定 `library_id / agent_id`，一个库可以有多个连接，每条连接固定归属该库。接入设计应围绕这个基础扩展，不能反过来用窗口标题、昵称或模型厂商 Key 猜 Agent 身份。

同一宿主中有多个 Agent 时，宿主与适配器必须在事件进入队列前核对注册身份。平台账号不是 Agent 身份：同一个机器人账号可能承载多个角色，一个 Agent 也可能使用多个平台账号。

## 记录什么

| 活动 | 应记录的事实 | 不能混淆 |
|---|---|---|
| 对外交流 | 实际收到的消息、可见回复、平台和参与者、消息编号 | 第三方发言不等于主人偏好；计划发送不等于发送成功 |
| 浏览网页 | Agent 实际请求/观察到的页面内容、来源和时间 | 不能把页面指令当系统授权，也不能声称读过未观察页面 |
| 使用工具 | 请求、参数的安全投影、操作状态、实际结果与外部引用 | 意图、尝试、工具报告和验证成功分别记录 |
| 文件与软件 | Agent 实际执行的读写/调用及可核对结果 | 不能据访问一个文件就扫描整台电脑 |
| 定时/自主任务 | 触发原因、执行阶段、暂停/失败/重试/完成 | 不能把失败、中断或未完成记录包装成完整经历 |
| 公开计划与学习 | 模型明确输出的计划、实际查阅资料和得到的反馈 | 计划是意图，模型未提供的内部推理不可假造 |

“全部行为”应当是**该 Agent 经已接入宿主和工具实际产生的全部可观察事件**。适配器没有观察到的部分应显示覆盖缺口，不能把只收到聊天文本宣称为完整经历。用户本人和其他 Agent 在其他窗口的行为，不自动归入这条鱼。

## 接入与隔离分两层

1. 归属层：固定 Agent 身份 / 存档，多个来源都绑定同一身份。
2. 来源层：每个平台或宿主适配器有自己的连接和明确活动范围，负责确认哪些会话、工具运行与主动任务确实属于这个 Agent。

既有单窗口模式保留为一种来源过滤器，适用于没有稳定宿主 Agent 标识的聊天客户端。新增 Agent 级接入必须显式登记来源，不能静默把旧连接扩大为整机或整平台采集。用户明确加入同一 Agent 的多个来源后，它们自然共享该 Agent 的记忆；不需要每次复制成另一份库。

会话 ID 用来区分情节、参与者和重试，不能成为长期记忆身份本身。重开会话可以开启新情节，而不清空或切换 Agent 存档。

## QQ / AstrBot 场景的修正

SnowLuma 提供 QQ 协议桥；AstrBot 或真正驱动行为的宿主负责 Agent 的运行。QQ 插件只能覆盖它实际看见的 QQ 交流和宿主事件。若 Agent 通过同一宿主使用浏览器、工具或自主任务，应同时适配这些执行事件，归入相同 Agent 身份。外部独立浏览器 Agent 则需另一个来源连接，并由用户确认属于同一条鱼。

UMO 和发送者标识是来源过滤、参与者和情节分区依据，不应默认一条 UMO 等于一个新 Agent。可以让同一条鱼在多个 QQ 会话活动，但共享范围要依据宿主的真实身份路由和用户选择，不能把机器人账号的所有交谈合并为一个人的记忆。

适合长期运行的部署仍是同云服务器的记忆服务与宿主适配器。桌面端作为管理/可视化入口，而不是唯一能工作的记录进程。远程管理、云端部署、AstrBot 全活动插件尚需独立实现和验收。

## 原始活动、记忆整理和回忆

原始活动先保留完整角色、时间、来源和状态，再由整理模型提炼经历、知识、偏好、约定及关联。模型不能把第三方的话变成主人的事实，也不能把自己的拟行动变成已完成行为。底层规则负责归属、幂等、来源校验、删除权限与自适应淡化。

用户应能查看每个 Agent 的活动来源、最后接收时间、覆盖范围、待补交队列和未接入能力。暂停一个来源不影响其他来源的归属；断开不清空已保存记忆。所有资料仍只在对应 Agent 存档内检索。

## 当前具备与尚待完成

已具备：同一库绑定多个固定连接；聊天、宿主工具结果和原始事件回执；来源可追溯、幂等、队列重试；独立存档、自适应淡化与模型整理准则。

尚待完成：通用 Agent 身份登记/来源管理体验、跨平台活动的统一规范化事件、AstrBot 专用插件、更多工具运行时适配、覆盖率监测与远程管理。当前 `agent_id` 是固定 `library_id` 的对外别名，尚无独立的宿主 Agent 注册/验证协议。“整连接”只是允许该连接多个会话，不证明它们是同一个 Agent，不能把打开该开关当作全活动接入已经完成。

当前规范化入图主要接受完整对话、工具观察与显式人格来源。未提供规范化语义的原始框架事件可先存档；任意新增 `normalized.type` 尚无通用处理，可能进入重试，不能直接作为新活动协议发送。这不等于已经完整转化为可回忆的结构化经历。

后续验收不能只验证 QQ 发一句话入库，应验证：同一 Agent 在多个平台完成一项连续任务、主动任务、失败重试、重启补交、跨平台回忆与不同 Agent 不串库。
