# 空闲回顾：公开机制研究与爱之屋设计约束

研究与独立审查日期：2026-11-04。本文记录已阅读的公开原始资料、设计约束与本次核验范围，不代表功能已经发布。当前状态为：**核心与主机服务已实现，模拟模型测试通过；独立效果评测、完整界面验收和发布仍为 pending**。

## 结论与能力边界

爱之屋可以借鉴后台记忆整理和经过验证的经验回放，改善后续检索、整理与回应时使用的外部记忆。**API 外部记忆与本地控制的回放，不等于训练模型参数。** 调用用户选择的 API 模型、改写外部记忆或调整检索策略，不会因此改变服务端模型的权重、架构或基础能力。

目前核实到的相关实现分为三类。没有用户提供的报道链接，不能确定报道所指的是哪一类，也不能把第三方集成称为 OpenAI 内置能力。

| 机制 | 已核实的实际工作 | 与爱之屋的关系 |
| --- | --- | --- |
| OpenAI Codex 后台记忆 | 从合格的空闲会话抽取信息，合并为本地文件记忆，供后续会话使用；包含增量处理、任务租约与并发协调 | 可以借鉴调度、来源管理、失败恢复和提交验证；不是参数训练 |
| 微软 SkillOpt-Sleep | 冻结目标模型，从历史任务回放产生反馈，以有边界的文本修改改进技能或记忆，使用独立验证任务决定接受或拒绝 | 可以借鉴经验提案、独立验证、模拟数据标记和防止学习循环；不是 OpenAI 官方内置 sleep 功能 |
| Google Research SLEEP | 论文研究通过参数层面的记忆组织、容量扩展、蒸馏和合成练习进行持续学习 | 标准 API 应用不能直接复制其参数级能力；不能把爱之屋的外部记忆整理宣称为同等实现 |

这里的“做梦”是技术比喻，不表示软件产生真实经历或意识。合成练习只能帮助比较策略，不得变成人物经历、用户陈述或真实事件的证据。

## 爱之屋建议流程

以下是爱之屋的设计流程；核心与主机接入的已核验范围见文末，不是上游产品能力声明，也不代表每一步已具备独立效果证据：

1. 在记忆库空闲时，从用户已经连接、允许整理的来源中领取新增或变更任务；读取范围取授权区域的并集。
2. 固定本次输入快照，保留每条来源的标识、版本、内容摘要、库与区域身份；整理输出只产生带证据的候选。
3. 合并重复表达，整理时间线、关系和明确反馈；事实、推断、建议与模拟练习使用不同状态。
4. 对候选执行结构检查、证据检查、授权检查和回放比较。安全边界采用确定性检查；模型评分只能辅助判断内容质量。
5. 以事务复核本次来源和授权仍有效，再提交允许自动应用的变化；需要用户取舍的变化进入现有候选审阅机制。
6. 持久化覆盖记录、失败原因与下一次重试时间。工作批次结束后继续剩余任务，不能把部分完成记成全库完成。

回放使用与真实聊天隔离的只读快照，不调用窗口操作、发消息、修改用户原始内容或新增连接。流程在本机编排不表示模型推理离线：选择 API 模型时，相关输入仍会发送给用户配置的服务商。沿用现有模型、模型强度、上下文与授权设置，不能偷偷降级或改用另一家服务。

## 必须落实的设计约束

### 范围、来源与撤销

- 记忆库和用户连接区域都是边界。同库多个已授权窗口可以共同参与，未连接窗口不能被发现后自动加入。
- 每个作业记录具体的 `library_id`、`source_id`、来源修订或内容摘要、授权版本，以及真实输入或整理输出的来源类型。
- 推理完成不等于可以提交。事务内重新校验库身份、连接授权、来源修订和删除标记；任一变化使旧候选失效，应取消或重新计算。
- 删除、遗忘与纠正必须传递到派生结论、索引、回放快照和可恢复记录；不能从旧摘要复活已删除内容。若仍有其他有效来源支持，应只保留其实际支持的部分。
- 一个区域的授权不能被另一区域的同名标题、相似文字或相同人物名替代。跨区域来源冲突要保留原范围，不能自动扩散为全局事实。

### 调度、并发与失败恢复

- 按记忆库持有独占作业租约；作业带随机所有权凭证并定时续租。过期 worker 不得覆盖新 worker 的结果。
- 模型调用、验证与提交分开。持久化待处理状态，应用事务应短；不在等待外部 API 时长期占用数据库写事务。
- 提交前验证所有权仍有效；未确认后台 worker 停止时，不提前放行会与其竞争的作业。
- 成功覆盖记录绑定具体输入版本。失败不推进成功水位；仅按最大时间戳推进，可能遗漏较早时间戳的迟到输入，必须有来源版本或逐项覆盖记录。
- 新增输入进入后续批次，失败按原因退避重试。超时、格式错误、服务限流、凭证或服务配置错误均不得造成“已完成”的假状态；缺少有效配置的作业可解释地等待修正。
- 批次大小、并发数和服务端上下文限制是单次执行约束，不是记忆库容量上限。有效积压必须能继续处理，不能因为达到本机写死的每日次数或字符额度而永久搁置。
- 不保证故障服务一定能成功。“直到全部整理好”应体现为不丢任务、持续恢复、可查看未完成原因；不能用无限密集重试代替恢复机制。

### 防止循环学习与虚构经历

- 原始对话、用户反馈、整理摘要、反思提案和模拟任务必须有可验证的来源类型。整理和回放输出不得伪装为用户原话。
- 空闲回顾任务本身不成为下次抽取的真实经历，不增加真实用户使用次数，也不能以自己生成的文本作为独立佐证。
- 合成任务保留原任务关系与模拟标记，仅用于策略练习。不能进入事实记忆、偏好证据统计、验证集或测试集。
- 后来的明确纠正优先于旧结论。一次任务要求不能自动变为长期偏好，普通行为也不能自动推断为固定人格。
- 不允许根据低分或不合意反馈自动重写用户目标、人物核心身份、授权范围或遗忘规则。

### 验证、证据与可撤销变更

- 同一批原始案例及其改写必须属于同一分区；训练、验证和测试按原始来源划分，不能靠改写绕开独立验证。
- 比较同一快照下的原策略和候选策略，保留输入版本、模型标识、评分规则、结果与差异。没有独立有效证据时，只能显示未验证提案，不能显示“能力提升”。
- 未授权区域访问、删除内容复活、错误人物归属、伪造证据属于阻断项；不能以平均分提升抵消这些退步。
- 回放覆盖空证据、重复事件、不同窗口同名人物、矛盾来源、纠正、运行中撤权、旧 worker 迟到和重启恢复。
- 语义评分必须评估任务结果，不能仅检查标题、关键词或输出长度。不能将评测答案或隐藏规则直接复制到学习文本中。
- 变更记录支持定位和撤销错误整理；遗忘具有更高优先级，撤销不能恢复已被用户删除或撤销授权的信息。回滚记录不应成为绕开遗忘的第二份永久记忆库。

## 独立审查与实施状态

本次只对具体实现和模拟数据作了核验。版本发布与真实用户效果须另行验证，不因引用上游机制或通过这些测试而自动满足。

已独立审查 [逐项处理与租约引擎](../../nkb/organizer/idle_review.py)、[来源与提案约束](../../nkb/companion/review.py)、[主机接入](../../nkb/service/idle_review.py)，以及 HTTP 图谱事务中的提交保护。当前实现使用用户已有的整理模型配置，默认关闭自动回顾；不会自动采纳策略或模拟材料。

离线复验结果：`py -3 -m unittest tests.test_idle_review tests.test_idle_review_service -q`，**32 项通过**，包括 27 项模块测试和 5 项使用真实本机 HTTP、临时记忆库及模拟模型的服务测试。[模块测试](../../tests/test_idle_review.py)、[服务测试](../../tests/test_idle_review_service.py) 均未访问真实付费模型。另对真实主机的 `Brain.persist` 注入延迟：让租约时钟超期并同时请求停止，确认停止等待已进入的提交结束，提案回执、日志、内存和磁盘状态一致。

审查中修复并复核了以下问题：完整模型输入都参与版本依赖校验，不能只追踪模型展示的引用；来源与授权在主机锁内最终复核；租约保护覆盖实际图谱持久化与提案状态写入，已保存的成功不能再因停止或时钟超期被报告为失败；缺失窗口范围与不匹配的注册来源身份拒绝供料。反思使用独立证据字段，撤回反思不误停用原始材料；同一次读取复用证据扫描结果，不跨请求缓存，后续来源更正或停用立即失效。未发现本次核验范围内尚未关闭的阻断问题。这不是对任意故障或任意输入的完全正确性证明。
