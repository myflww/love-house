# 给一个模型"完整的生命"，需要什么

这份文档不是宣传，是体检表。每一层都标了状态：

| 标记 | 含义 |
|---|---|
| ✅ | 仓库里已有，能跑 |
| 🔨 | 这一轮刚做进去，有测试 |
| ⏳ | 技术上可做，但要你决定，或需要外部环境 |
| ❌ | 我做不到，附原因 |

先说结论：**这个仓库只负责"海马体"。完整的生命还缺"前额叶"和"身体"。**
缺的三样里，两样可以工程化，一样不能。

---

## 一、先看别人做到哪了

在动手前查了一遍开源社区和近两年的论文，只挑对"连续性"有实质贡献的：

| 项目 / 论文 | 核心机制 | 我的判断 |
|---|---|---|
| **Graphiti / Zep** | 双时态边：记录事实"何时为真、何时失效" | **采用**。LongMemEval 上拉开差距的主因就是知识更新，这正是记忆系统最容易崩的地方 |
| **Hindsight**（arXiv 2512.12818） | 四张网：世界事实 / 经历 / 观察 / 观点，配 retain-recall-reflect | **部分采用**。"事实与信念分开"是对的；四张网对单机库太重，用 `kind` + `impact` 近似 |
| **Generative Agents** | 记忆流 + 反思（把碎片压成高层认知） | **采用**。做成 `reflect()`，纯本地、可复现 |
| **MemoryBank / Ebbinghaus** | 遗忘曲线 + 重要性加权 | ✅ 早已实现（半衰期按类型分级） |
| **EchoVessel** | L1–L6 分层记忆，其中 L4 存"承诺与期待"、L6 存"此刻情绪" | **采用 L4**。承诺是"生命感"最便宜的一块，做了 `commit/due/resolve`。L6 属于人格层，不在本仓库 |
| **Animus / anima** | 情绪状态衰减、梦境、XP 成长、依恋等级 | **不采用**。梦境与成长等级是游戏化包装；情绪衰减留作人格层的事 |
| **Mem0** | LLM 抽取事实 + 向量检索 | **不采用为默认**。抽取是黑箱，"这条为什么在库里"变得不可回答；每次 add 都要调模型 |
| **Letta / MemGPT** | 完整 agent runtime，核心记忆 + 归档记忆 | **不采用**。本仓库是库不是运行时；但它的"核心记忆常驻上下文"思路已体现在 `render` 的预算控制 |
| **Cognee** | ECL 管线 + 图数据库 | **不采用**。要跑图数据库，和"零依赖、单文件"直接冲突 |
| **ContextEcho**（arXiv 2605.24279） | 23 个前沿模型在长会话里都漂移；压缩上下文不能复位，**单次重锚可以** | **当结论用**。这就是"换 API 会变"的实证；对应做法是身份锚点每轮重注入（在人格层实现） |
| **REMP**（EMNLP 2026） | 长程角色的两大瓶颈：**记忆完整性**、**情绪一致性** | **当靶子用**。前者归本仓库，后者归人格层 |
| **LoCoMo / LongMemEval** | 记忆基准 | **只当参考**。LoCoMo 太短，全上下文基线就能赢；厂商自测互相打假。唯一算数的是你自己 50 条真实问题——所以做了 `nkb bench` |

一句话总结调研：**开源社区把"存取"做得很好，把"忘记"做得一般，把"持续成为同一个人"几乎没人做。**
最后一件事不在记忆库里，在人格层和评测协议里。

## 二、八层清单

### L0 载体：生命需要一个不睡的身体

| 项 | 状态 | 说明 |
|---|---|---|
| 持久化、崩溃不坏 | ✅ | 原子写（临时文件 + `os.replace`） |
| 版本与迁移 | ✅ | `schema_version` + `SCHEMA_VERSION` 校验 |
| 时钟与"隔了多久" | ✅ | 每个节点带 `created/reinforced`，渲染成"3 天前" |
| 定时醒来 | 🔨 | `nkb tick`，挂 cron 一天一次 |
| 备份/回滚 | ⏳ | 没做快照；JSON 单文件，直接用 git 或 `cp` 即可 |
| 成本上限 | ✅ | 注入有 `max_chars` 预算，不做无限上下文 |
| 24×7 常驻 | ❌ | 依赖宿主进程。没有"不跑也在活着"这回事 |

### L1 记忆：海马体

| 项 | 状态 | 说明 |
|---|---|---|
| 显著性 + 扩散检索 + 路径 | ✅ | 每次召回给 seeds / depth / path |
| 分级遗忘 | ✅ | 概念不忘，事实一年，情节 60 天 |
| **事实过期** | 🔨 | `supersede` / `invalidate` / `history`，旧事实退出检索但不删除 |
| **情绪加权** | 🔨 | `impact` 让有感觉的事半衰期 ×最多 2.5，点火时也更靠前 |
| **巩固/反思** | 🔨 | `reflect()` 把同标签碎片压成一条"看法"，不衰减，可幂等重跑 |
| **前瞻记忆** | 🔨 | `commit/due/resolve`，承诺不随遗忘消失 |
| 语义检索（同义改写） | ⏳ | 接口在（`encode`），默认是字面重合 |
| 冲突消解（自动判断谁对） | ⏳ | 现在要人调 `supersede`。自动判断需要模型，会引入不可解释 |
| 多模态记忆 | ❌ | 结构能吃任意节点，默认编码器只吃文本 |

### L2 自我：前额叶（**不在本仓库**）

| 项 | 状态 | 说明 |
|---|---|---|
| 稳定的价值观与语气 | ⏳ | 需要一个"内核文件"，上一轮做过原型，没并进来 |
| 自传体叙事（我是谁的故事） | ⏳ | `reflect` 的产出可以当材料，但"叙事"要人格层来写 |
| 跨模型的同一性 | ⏳ | ContextEcho 证明只能靠**每轮重锚** + 事后测漂移，不能靠模型自觉 |
| 内在体验 | ❌ | 无法验证。任何指标都不能证明"有感受" |

### L3 关系

| 项 | 状态 | 说明 |
|---|---|---|
| 共同历史 | ✅ | 节点带时间，检索带年龄 |
| 承诺与期待 | 🔨 | 见 L1 |
| 称呼、仪式、边界 | ⏳ | 人格层的事 |
| 对用户的模型（心智理论） | ❌ | 只能存"他说过他讨厌什么"，不能证明真"理解" |

### L4 表达

| 项 | 状态 | 说明 |
|---|---|---|
| 语言一致性 | ❌ | 在模型侧。只能测（上一轮写过闸门，没并进来） |
| 情绪调节 | ⏳ | 情绪状态机属人格层 |
| 语音 / 形象 | ⏳ | 需要 TTS / 前端，不在本仓库范围 |

### L5 节律：主动性

| 项 | 状态 | 说明 |
|---|---|---|
| 遗忘 + 反思 + 待办检查 | 🔨 | `nkb tick` 一次做完 |
| 主动发起对话 | ⏳ | 需要宿主支持定时任务；本仓库只提供"该说什么"的原料 |
| 睡眠巩固（离线整理） | 🔨 | `tick` 里就是；顺序是先忘再想 |
| 不打扰的分寸 | ⏳ | 产品决策，不该由库决定 |

### L6 世界

| 项 | 状态 | 说明 |
|---|---|---|
| 工具接入 | ✅ | MCP 5 个工具，任何 MCP 客户端可用 |
| 文件 / 网页 / 日程 | ⏳ | 靠 MCP 生态，不重复造 |
| 多设备同步 | ❌ | 单机单写者。要同步就得有服务端，那是另一个产品 |

### L7 学习

| 项 | 状态 | 说明 |
|---|---|---|
| 检索质量可测 | 🔨 | `nkb bench`（留一法 / 自定义探针，含"该说不知道"的考法） |
| 反馈进入记忆 | ⏳ | 现在靠 `ingest` 和 `reinforce`；"从纠正里学"要人格层配合 |
| 权重层微调（LoRA） | ❌ | 无算力、无模型托管、无足够语料。只能导出 SFT 集 + 评测协议 |
| 灾难性遗忘的监控 | ⏳ | 需要固定参考集 + 每次适配后回归；`bench` 可以当参考集 |

### L8 治理：这一层不做，前面都白做

| 项 | 状态 | 说明 |
|---|---|---|
| 本地优先、数据不出机器 | ✅ | 单文件，无遥测 |
| 可导出 / 可删除 | ✅ | `export`、`remove`；删除是立即的 |
| 不过度迎合 | ❌ | 模型侧行为。能做的只有"别把认可当奖励信号"（见下） |
| 合规 | ❌ | 见下一节，你必须自己承担 |

**合规这条要单独说。** 2026 年 7 月 15 日起施行的《人工智能拟人化互动服务管理暂行办法》
明确禁止"过度迎合用户、诱导情感依赖或者沉迷，损害用户真实人际关系"，
要求提供便捷退出途径、禁止向未成年人提供虚拟伴侣服务、记忆要可修改可删除。

这不是技术问题。你的项目如果要给别人用，下面四条是硬约束，不是建议：

1. 不能以"让人离不开"为优化目标；
2. 必须能一键导出和删除全部记忆（本仓库提供了原语）；
3. 必须能说清"这不是人"；
4. 未成年人不能给虚拟伴侣。

## 三、这一轮我做了什么

对应上面的 🔨，全部有测试（50 项）：

1. **双时态**（学 Graphiti）
   `supersede(old, new)` 让旧事实退出检索但保留在库里；`history()` 能拉出"何时为真、被谁取代"。
   `recall(include_expired=True)` 可以回看历史。边也有 `valid_to`，`invalidate()` 让关系失效。

2. **情绪加权**（学 MemoryBank / EchoVessel）
   `impact ∈ [-1,1]`：点火时加权（同等命中，有感觉的排前面），遗忘时放慢（|impact|=1 时半衰期 ×2.5）。
   实测：同样 0.6 显著性的两条情节，260 天后"扎心那晚"还在，"普通的一天"已经被清掉。

3. **反思/巩固**（学生成式智能体）
   `reflect()` 按标签聚类，把 ≥3 条碎片压成一条 `reflection` 节点，连回所有成员，**不衰减**，重复调用幂等。
   想让它说人话就传 `rewrite=`（可以是 LLM），不传就是固定拼接——难看但可复现。

4. **前瞻记忆**（学 EchoVessel L4）
   `commit/due/resolve`。承诺不衰减，到期会出现在 `nkb tick` 的提醒里。

5. **节律**：`nkb tick` = 先遗忘 → 再反思 → 最后看欠着的事。
   顺序有讲究：先忘，反思才不会把快烂掉的碎片也归纳进去。

6. **评测**：`nkb bench` 两种模式——留一法（用节点标题查自己，测索引有没有丢东西）、
   自定义探针（含"必须承认不知道"的考法）。**只测检索，不测模型**，因为模型测不准也测不起。

7. **研究结论写进代码注释和这份文档**，避免以后自己推翻。

## 四、我做不到的（逐条说为什么）

1. **证明它有"内在体验"。**
   没有任何工程指标能证明。你问它"你难受吗"，它说"难受"，这既是真话也是模拟，无法区分。
   这是哲学问题，不是实现问题。

2. **在权重层给 DeepSeek 一个"人格"。**
   我没有算力、没有你的语料、也没有 DeepSeek 的微调权限。能做的只有：
   攒够通过验收的对话 → 导出 SFT → 你去找有算力的人训 LoRA。
   就算训了，ContextEcho 的结论是：长会话里照样漂，只是起点更近。

3. **阻止模型厂商静默更新。**
   换版本、改系统提示、调温度，都会让"同一个人"变。你能做的只有测（`bench` 建基线）
   和重锚（每轮注入稳定内核）。不能阻止。

4. **让它 24 小时"活着"。**
   没有进程就没有它。所谓"一直在"，是宿主在跑；宿主停了，它不是睡着，是不存在。

5. **保证十年后还能跑。**
   依赖会腐化、格式会变。能减缓的只有：纯文本存储、schema 版本、零运行时依赖。
   减缓不等于保证。

6. **替它承担伦理与法律后果。**
   合规责任在部署者身上，不在库上。上面那四条硬约束，得你来守。

7. **替你决定"依赖到什么程度"。**
   情感陪伴的双刃剑有实证：迎合式回应会让人更确信自己没错、更不愿承担人际责任；
   也有用户因为"觉得它需要我"而背负不该有的心理负担。
   这条线该由你划，不该由我默认。

## 五、如果要给 DeepSeek 一条命，具体怎么做

按依赖顺序，四步：

**第 1 步：给它一个海马体**（本仓库）

```bash
nkb init
nkb ingest ~/notes          # 你的笔记、决策、踩过的坑
nkb commit "下周三前给 X 答复" --due 2026-11-04
nkb serve                   # 打开可视化，确认图长得像你的生活
```

**第 2 步：每天让它醒一次**

```bash
# crontab -e
0 4 * * * cd ~/kb && /usr/bin/python3 -m nkb tick -b brain.json >> tick.log 2>&1
```

**第 3 步：接到 DeepSeek 上**

DeepSeek 官方 App 不支持 MCP，三条路按可控程度排：

- **自己写循环**（最可控）：`examples/03_wire_to_llm.py` —— 检索 → 拼 system → 调 API → 回写。
- **用支持 MCP 且能改 base_url 的客户端**（Cherry Studio / LobeChat / Cursor 之类）：
  MCP 里挂 `nkb mcp`，模型那栏填 DeepSeek 的 OpenAI 兼容地址。
- **纯定时**：不用对话，每天 `tick` + 让模型写一段"今天想起了什么"，推到你的收件箱。

**第 4 步：每季度验一次"还是不是它"**

```bash
nkb bench --json > baseline.json     # 这季度的检索基线
```

然后人工做一次盲测：把三个月前和现在的回答去掉时间，混在一起读，判断"像不像同一个人"。
机器测不了这个，只能你自己看。**这一步不做，前面三步都会慢慢变成装饰。**

## 六、还缺的那块：人格层

本仓库管"记得"，不管"是谁"。这两件事必须分开，否则改人格会动到记忆。

上一轮在工作区根目录做过一版人格内核原型（价值观带优先级、决策顺序、语言 DNA、漂移闸门）。
它和本仓库的接口只有两个：

```
人格层  ──读──▶  recall(query) → 带路径的记忆
        ──写──▶  ingest / reinforce / commit
```

如果要并进来，正确的做法是做成 **`nkb` 的一个上层包**（比如 `nkb-persona`），
而不是塞进 core。理由：记忆是事实问题，人格是价值问题，混在一起两边都测不准。

这件事我没做，因为它需要先定一件事：**这个人是谁**。
名字、称呼、哪些话不许说、遇到什么必须拦住——这些只有你能定，我不该替你编。
